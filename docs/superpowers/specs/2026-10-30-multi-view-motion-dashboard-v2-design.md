# 多界面动作捕捉开发台 V2 设计说明

日期：2026-10-30

## 目标

将当前纵向长页面重构为固定应用外壳下的多界面开发台。主界面、设备标定、历史记录与导出、姿态回放、高级设置分别占据独立视图，用户只能通过左侧导航切换，不再通过锚点滚动进入功能区。

视觉继续以 `docs/ui/references/dashboard-glass-v1.png` 和 `docs/ui/references/calibration-glass-v1.png` 为基准，但所有人体、节点、曲线、状态和回放内容必须由现有实时数据与 Canvas 绘制，不能把参考图作为页面内容或背景。

## 范围与约束

- 保留 USB/Wi-Fi 连接、设备绑定、零偏校准、方向标定、十四节点、分层诊断、记录、导出和回放能力。
- 不修改后端接口、命令名称、WebSocket 地址或数据结构。
- 不引入真正的 3D 模型、WebGL 框架或外部 CDN。
- 桌面端的主界面和标定界面在 1920×1080、1366×768 下均应作为一个完整视图呈现，不能依赖主页面纵向滚动。
- 窄屏允许当前独立视图内部纵向滚动，但不能产生横向溢出；导航固定在底部或折叠为紧凑栏。
- 等待、操作中、成功、失败、断线、失鲜、模拟输入和回放状态必须显式展示。

## 应用结构

应用采用单页多视图结构，而不是多份相互复制的 HTML。固定外壳包含顶部状态栏和左侧导航，内容区只显示一个 `.app-view`。路由使用 URL hash，支持刷新后保持当前视图：

- `#/dashboard`：实时总览。
- `#/calibration`：设备连接、节点绑定和标定。
- `#/records`：历史记录浏览、详情预览和导出。
- `#/replay`：姿态回放。
- `#/advanced`：实验位移、坐标轴、融合策略和详细诊断。

左侧导航按钮改变当前路由和可见视图，不执行页面锚点跳转。切换视图不重建 WebSocket、不清空实时缓存、不停止录制，也不改变已选择设备。

## 实时总览界面

总览遵循第一幅参考图的密度与层级：

- 左侧设备区：USB/Wi-Fi 状态、连接入口和十四节点在线状态。
- 中央舞台：中性人台、十四节点、观察工具和实时状态说明。
- 右侧状态区：接收质量、设备状态和标定概况。卡片在 1366×768 桌面视口内完整呈现，不使用独立纵向滚动条。
- 底部遥测区：加速度、角速度、磁场曲线以及开始/停止记录入口。

总览只保留日常监控和高频操作。点击设备、标定状态或记录入口可切换到对应独立视图，但不在总览中展开长表单。

## 中性人台与交互

人体不使用真实 3D 模型，而是基于现有十四骨段实时坐标生成具有体积感的 Canvas 人台：

- 使用头部椭圆、肩胸轮廓、骨盆轮廓和四肢渐变胶囊组成连续中性剪影。
- 不绘制胸肌、腹肌、生殖特征或明显性别特征。
- 十四节点显示在对应骨段位置，编号和状态颜色与节点列表一致。
- 未连接时显示配置定义的中立站姿；实时帧到达后，人台完全跟随现有 `body_frame.segments`，不推测缺失动作。
- 鼠标普通拖动调整观察偏航角和俯仰角；俯仰限制在不会倒置界面的范围内。
- `Shift`+拖动平移观察中心；滚轮和缩放滑杆调整缩放；重置按钮恢复正面视角。
- 触摸屏单指拖动旋转，缩放仍由界面滑杆完成。
- 观察操作只改变相机投影，不修改传感器姿态、记录数据或回放帧。

## 设备标定界面

标定界面采用第二幅参考图的五步流程：

1. 连接设备。
2. 绑定十四身体节点。
3. 静置零偏校准。
4. 方向标定。
5. 完成与验证。

顶部显示步骤进度。左侧显示人台及已选节点，中央显示当前步骤的姿态说明、实时质量和操作按钮，右侧显示计时、稳定性和应用结果。切换步骤只改变当前步骤内容，已完成步骤和设备状态继续保留。

### 单节点重新标定框

标定界面增加独立的“单节点重新标定”显示框，复用原仓库的选中设备详细检测能力：

- 从在线设备或十四槽位中选择单个物理节点。
- 显示节点名称、绑定槽位、连接/失鲜状态、Roll/Pitch/Yaw、温度、三轴传感器值和稳定性。
- 提供“重新采集零偏”“取消校准”“重做方向标定”“恢复当前姿态参考”操作。
- 零偏重新采样只作用于所选节点，不清除其他节点已接受的零偏与安装标定。
- 若重新做方向标定需要父子节点共同参与，界面明确列出作用范围并沿用现有方向标定命令，不能伪装成单节点独立完成。
- 操作期间显示准备、采集中、稳定性不足、成功、失败和超时状态；晚到回执不能覆盖新的操作状态。

该框默认收起或以右侧抽屉/对话框打开，避免挤压五步主流程；点击人台节点或节点列表中的“重新标定”进入。

## 历史记录与导出界面

记录浏览与导出合并在同一视图，避免为一次导出再增加空白页面：

- 左侧约 30%：会话列表、刷新、状态筛选和当前录制状态。
- 中央约 45%：所选会话的时间、时长、样本数、骨架帧数和三类曲线预览。
- 右侧约 25%：完整性、来源、配置摘要以及导出 ZIP/CSV 操作。

未选择会话时中央显示清晰空状态，而不是复制主界面。正在录制的会话不能回放或导出，继续沿用现有冲突提示。导出仍使用现有接口和文件内容。

## 姿态回放界面

回放是独立视图，不在历史记录弹窗中播放：

- 中央为可拖动旋转的中性人台和十四节点。
- 右侧为会话信息、播放速度、帧状态和回放/实时来源标识。
- 底部为播放、暂停、逐帧、时间轴和三类同步曲线。
- 从历史记录点击“打开回放”后进入 `#/replay` 并载入该会话。
- 回放必须使用保存的实际骨架帧；切换视图或暂停不允许实时输入覆盖回放模型。
- “返回实时”退出回放并回到总览；断线状态仍保留在全局顶部状态栏。

## 高级设置界面

高级设置容纳低频和实验功能：

- 融合策略与停稳保持。
- 实验位移、板卡轨迹和坐标轴映射。
- 原始传感器表格、分层诊断和方向标定证据。

高级内容可以使用局部折叠面板和内部滚动，但不能改变其他视图的状态。

## 前端组件边界

- `index.html`：固定应用外壳、五个视图和现有控件 ID。
- `style.css`：视觉系统、固定视口布局、各视图网格和响应式规则。
- `navigation.js`：hash 路由、导航状态、视图显示和跨视图入口。
- `body_view.js`：人台几何、十四节点、相机拖动/平移/缩放和 Canvas 绘制。
- `body_app.js`：身体状态、标定流程、记录/回放命令及视图数据刷新。
- `app.js`：单节点数据、曲线、连接和旧记录接口。

路由层只切换表现状态，不复制或接管业务状态。现有 DOM ID 在迁移后继续存在，以保持 `app.js`、`body_app.js` 和 `direction_app.js` 的事件绑定兼容。

## 响应式行为

- 1920×1080：完整三栏总览；底部曲线可见。
- 1366×768：压缩字号、间距和面板高度，仍完整显示主界面的三栏和底部曲线；右侧状态区不出现滚动条。
- 小于 900px：独立视图改为纵向内容流，左侧导航固定到底部。
- 430px：人台优先，卡片单列，控件不小于可触摸尺寸，不出现横向溢出。

## 错误与状态

- WebSocket 断开：全局顶部显示断线与重连，视图保留最后数据并标记失鲜。
- 无设备：显示中立人台和明确空状态，不显示伪造的在线曲线。
- 操作中：按钮进入 `aria-busy` 并防止重复提交。
- 失败或超时：在当前视图和全局反馈区同时显示可执行的恢复建议。
- 回放中：实时连接状态仍可见，但所有姿态和曲线明确标为回放来源。

## 验证标准

- 导航点击后只出现目标视图，URL hash 与选中导航一致；不存在从总览滚动到其他功能区的路径。
- 主界面在 1920×1080 和 1366×768 截图中同时显示三栏和底部曲线，无主内容区纵向滚动或右侧栏滚动。
- 430×932 无横向溢出，底部导航不遮挡主要操作。
- 人台可用鼠标拖动旋转，重置后回到正面，拖动不改变底层骨架数据。
- 十四节点、等待/成功/失败/断线/失鲜状态均有自动化或静态契约测试。
- USB/Wi-Fi、绑定、零偏、方向标定、单节点重新标定、记录、导出和回放的现有测试继续通过。
- 参考图文件名不出现在生产 HTML/CSS 的背景或图片引用中。

## 明确不做

- 不引入真实 3D 人体资产、Three.js 或 WebGL。
- 不增加后端页面路由或新的数据协议。
- 不把历史记录浏览与姿态回放塞回总览弹窗。
- 不为纯视觉效果伪造在线设备、接收频率、传感器曲线或标定成功状态。
