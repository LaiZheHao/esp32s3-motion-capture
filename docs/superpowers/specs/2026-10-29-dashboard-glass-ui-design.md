# 深色玻璃拟态动作捕捉开发台设计

日期：2026-10-29

## 目标

在不修改后端接口、WebSocket 消息结构和动作捕捉数据处理链的前提下，将现有开发台改造成适合日常操作的深色玻璃拟态界面。页面以实时人体姿态为视觉中心，同时保留 USB/Wi-Fi 连接、设备绑定、零偏校准、方向标定、十四节点诊断、记录和回放等全部现有能力。

视觉参考：

- `docs/ui/references/dashboard-glass-v1.png`：主开发台的布局、材质、色彩和信息密度。
- `docs/ui/references/calibration-glass-v1.png`：标定步骤、稳定状态和操作反馈。

参考图只定义视觉语言和布局关系，不作为页面背景或数据展示替代物。人体、节点、曲线、数值和状态继续由现有实时数据和 Canvas 绘制。

## 实施边界

### 保持不变

- FastAPI 路由、`/ws/body` WebSocket 和消息字段。
- `BodyRuntime` 命令名称和参数。
- 设备身份、身体槽位、冲突隔离、校准、记录及回放语义。
- 现有 HTML 控件 ID。已有 JavaScript 通过 ID 绑定事件，改造期间保持这些 ID 唯一且可用。
- 原始测量、融合姿态、记录文件和回放数据来源。

### 允许调整

- `index.html` 的语义分组、控件位置和可折叠层级。
- `style.css` 的全部视觉和响应式规则。
- `body_view.js` 的 Canvas 呈现，包括人体形态、节点光效、网格、配色和标签。
- `app.js`、`body_app.js`、`direction_app.js` 中纯前端展示状态、导航、面板开合和辅助文案。
- 前端测试中与新布局直接相关的结构和响应式断言。

不引入 React、Vue、Three.js 或远程字体/图标依赖。页面继续离线运行，使用原生 HTML、CSS、JavaScript 和 Canvas。

## 信息架构

页面使用一个固定应用外壳，桌面端分为四个区域：

1. 左侧一级导航；
2. 中央实时人体姿态和十四节点；
3. 右侧接收质量、设备状态和标定状态；
4. 底部实时曲线、记录及回放控制。

### 顶栏

顶栏显示产品名称、服务连接状态、当前 LIVE/REPLAY 模式、有效设备数、当前传输方式和接收频率。等待、在线、回放、断线和异常使用不同状态色，并保留文本说明，不能只依赖颜色。

### 左侧一级导航

一级导航使用图形加文字标签，切换或滚动到以下工作区：

- 总览；
- 设备；
- 标定；
- 数据；
- 记录；
- 高级设置。

桌面端为左侧窄栏。窄屏下改为底部导航或横向滚动标签，不占用正文宽度。

### 中央实时姿态

中央区域包含：

- 固定根部人体 Canvas，作为主视图；
- 十四身体槽位节点；
- 当前选中槽位和设备摘要；
- 模型视角重置、缩放和视图切换；
- 未测量、未初始化、在线、延迟、失鲜、断线、冲突和无效状态。

人体为中性、无明显性别特征的简化人台。实现方式是在现有骨架线段周围绘制柔和的躯干、骨盆、头部和四肢轮廓，并叠加实时骨段和发光节点。不得绘制胸肌、腹肌、乳房或其他解剖细节。未接入节点保持低亮度，不能推测动作。

人体节点继续支持点击选择。选中节点显示紫蓝外环和相应设备摘要，状态颜色保持可区分。

### 右侧状态栏

右侧按重要性排列三个日常状态卡：

- 接收质量：频率、序号缺帧率、包龄、无效帧；
- 设备状态：端点、传输方式、身体绑定、在线/失鲜状态；
- 标定状态：零偏、安装方向、停稳保持及当前操作阶段。

卡片必须展示等待、处理中、成功、失败、断线和失鲜状态。错误信息保留可读原因，不能只显示通用红点。

### 底部数据与记录

底部固定展示三张实时 Canvas 曲线：

- 加速度；
- 角速度；
- 磁场。

曲线继续使用现有数据更新和绘制逻辑。记录控制位于同一区域，包含开始/停止记录、会话选择、回放、暂停、时间轴和返回实时。录制与回放互斥状态必须保持。

### 设备与标定工作区

连接、端点管理、设备绑定和主来源选择放在“设备”面板。方向标定采用与参考图一致的步骤表达：

1. 连接设备；
2. 绑定身体节点；
3. 静置零偏校准；
4. 中立与前举方向标定；
5. 应用并完成。

这只是前端步骤映射，不合并后端命令。每个按钮仍调用原有独立命令，并展示服务端确认、采样进度、候选结果和失败原因。

### 高级设置

以下功能默认收起并集中到高级设置：

- 实验惯性位移；
- 选中设备板卡视图和轨迹；
- 坐标轴映射与位移符号；
- 融合策略和停稳保持细节；
- 分层诊断 JSON；
- 各设备板卡姿态角；
- 单节点历史记录对话框。

收起只影响视觉，不停止需要持续运行的数据流程，也不改变录制内容。

## 视觉系统

页面背景使用深蓝黑渐变和低对比光晕，不使用参考图。面板使用半透明深色、细描边、背景模糊和柔和阴影。强调色以靛蓝、紫色和冷蓝为主；成功使用绿色，警告使用琥珀色，失败与断线使用红色。

主要设计变量集中在 CSS 自定义属性中，至少包含背景、面板、边框、主文字、次文字、主色、成功、警告、错误和三轴曲线色。交互控件提供 hover、focus-visible、active、disabled 和 aria-busy 状态。

所有文字保持足够对比度。玻璃模糊不可作为区分边界的唯一手段；不支持 `backdrop-filter` 时仍须由面板底色和边框保持可读。

## 响应式规则

### 1920×1080

保持完整四区布局。人体主视图占中央主要空间，状态卡在右侧，三张曲线并排。

### 1366×768

缩小间距和面板内边距，左侧导航保持窄栏；右侧状态卡压缩但不隐藏关键文字；曲线仍优先并排，必要时降低高度。首屏应包含人体、关键状态和记录按钮。

### 窄屏

- 页面改为单列，不设置固定最小宽度；
- 左侧导航转换为底部导航；
- 顶栏允许换行；
- 表单控件宽度不超过容器；
- 曲线纵向堆叠；
- 人体 Canvas 高度按视口限制；
- 设备和标定面板使用全宽；
- 表格和原始诊断只在各自内部滚动；
- `document.documentElement.scrollWidth` 不得大于视口宽度。

## 状态与错误处理

现有 `commandFeedback` 继续作为统一操作反馈，视觉上改为顶部悬浮通知。命令发送后显示等待状态；收到命令确认后显示成功或错误；15 秒未确认时明确提示结果未知。WebSocket 断开时保留最后姿态但标记为失鲜，并显示自动重连状态。

LIVE 和 REPLAY 必须有明显区别。回放时禁止用户误以为数据仍来自实时设备。记录、回放、校准互斥造成的禁用必须保留原因文案。

## 验证

1. 运行完整 Python 测试：

   `python -B -X utf8 -m unittest discover -s tests -v`

2. 运行 CI 中现有 JavaScript 语法和回归测试。
3. 启动 `host/run_dashboard.py`，确认无硬件时仍能打开、连接 WebSocket 和读取串口列表。
4. 生成并检查以下截图：
   - 1920×1080；
   - 1366×768；
   - 430×932 窄屏。
5. 检查三个尺寸均无页面级横向溢出。
6. 检查 DOM ID 唯一，全部现有控制器引用仍能找到元素。
7. 检查 Canvas 仍由实时状态驱动，参考图没有出现在 CSS 背景或页面内容中。
8. 检查等待、成功、失败、断线、失鲜、录制和回放状态。

## 验收标准

- 页面视觉与两张参考图使用相同的深色玻璃拟态和紫蓝强调语言。
- 主页面首屏突出人体、十四节点、接收质量、设备和标定状态。
- 所有原有用户能力仍可访问，日常功能和高级功能层级清楚。
- 人体没有明显性别和解剖细节。
- 后端接口和 WebSocket 数据结构没有变化。
- 三个目标尺寸无页面级横向溢出。
- 现有自动测试通过，新增的前端结构测试通过。
- 视觉截图确认没有遮挡、裁切、不可读文本或失效控件。
