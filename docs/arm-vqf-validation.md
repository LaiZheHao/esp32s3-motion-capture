# 双 VQF 手臂验证

这是一条独立的实板试验入口。两块板发送板端 `[FUSION1]` 四元数，主机不重新运行原互补滤波，不修改现有 Wi-Fi 收发逻辑。它没有替换原全身页面，也不是完整 SlimeVR Server 的迁移。

## 硬件与启动

2026-11-27 接入的节点：

| 部位 | USB | 设备 ID | 固件 |
|---|---|---|---|
| 上臂 | COM6 | imu_149B6077C398 | imu-slime-vqf-20261127-r1 |
| 前臂 | COM9 | imu_305A6077C398 | imu-slime-vqf-20261127-r1 |

两块板使用同一 `esp32-s3-slime-vqf` 构建，身份仍由各自 MAC 生成，不将身体部位写死到固件。COM6 烧录前的完整 4MB 备份保存在本机忽略目录 `host/hardware_tests/arm-vqf-20261127/nodeB-before-vqf.bin`，SHA256 为 `E300FB9A99A2F94A23CDD7682EE5EA824B0E9230E6850E95D9DA515A3BFA82D4`。备份可能包含本地网络配置，不提交。

停止占用这些串口的单板显示服务后，从仓库根目录启动：

```powershell
host/.venv/Scripts/python.exe -B -X utf8 tools/live_arm_vqf.py --upper COM6 --fore COM9 --upper-device imu_149B6077C398 --fore-device imu_305A6077C398 --capture host/hardware_tests/arm-vqf-20261127/live.jsonl
```

窗口：<http://127.0.0.1:8002/>。每个串口只由该服务读取。服务会核对设备 ID 与 VQF 固件版本；错误设备不能参与骨架求解。记录包含原始 IMU3、板端姿态、设备身份、零偏、静止判定、中立参考、骨长和约束前后位置。数据只留在本机。

## 中立姿态与坐标

1. 两板先静置，等待启动零偏校准及 VQF 静止判定。
2. COM6 固定上臂、COM9 固定前臂，不跨肘；手臂下垂、肘伸直，两板 +X 轴水平朝身体正前方。填写肩到肘、肘到腕的实际长度。
3. 点击采集中立姿态，保持 1.2 秒。每节点至少 20 帧且全程静止，姿态离散不超过 3°。采集失败需重试。
4. 固定上臂，缓慢向前屈肘，再伸直。观察原始骨架与约束骨架，并保存这一段记录。

世界坐标为 X 前、Y 左、Z 上，四元数为主动旋转 WXYZ。每节点平均中立姿态为 `q0`；中立 +X 的水平投影给出各自融合坐标到约定世界前方的航向旋转 `H`，骨段姿态为 `H * q * inverse(q0) * inverse(H)`。这依赖用户的实际佩戴方向，无法仅从静止数据验证两板是否真的朝同一方向；当 +X 接近竖直时拒绝标定。桌面参考不能当成实际佩戴参考。

## 求解与约束

肩部固定为原点，上臂、前臂中立方向均为 −Z。肘位置由上臂姿态和骨长得到，腕位置由前臂姿态和骨长得到。固定骨长及关节连接从正向运动学直接保证，不双积分加速度求位置。

相对姿态 `inverse(q_upper) * q_fore` 投影到上臂局部 −Y 轴，屈肘角限制为 0–150°，得到第二条骨架。这是人为规定的平面屈伸试验约束，不是经过人体功能动作标定的完整肘模型；旋前、旋后和非平面动作也会被移除。轴投影奇异时单独标记。角度界限是实验设置，不作为个人生理范围判定。

页面“腕位置修改”“移除旋转”只是约束作用幅度，不是测量误差。验证真实精度仍需已知角度夹具、视频或外部位置参考。共同航向漂移、肩部平移、躯干运动无法由这两个六轴节点和此约束独立恢复。

## 时序与失鲜

板端姿态目标 25Hz，主机按各 USB 接收时间缓存最多 300 帧，延迟 80ms 进行四元数插值。只在两边都有包围目标时刻、间隔不大于 200ms 的样本时解算，不外推。最新姿态超过 500ms、连接中断、板端未就绪时不生成新骨架。重启、断开重连、融合重新校准会清除中立参考。页面缺帧计数从服务连接后的第一帧开始。

电脑接收时间不能代表精确采样同步；设备微秒时间和序号同时记录以便后续分析。记录中约束模型与原始姿态均保留，显示开关不改变融合输入或固件。

## 检查

`host/tests/test_arm_vqf.py` 覆盖已知 90° 屈肘、骨长、越界与非平面约束、两节点独立航向坐标及安装方向、中立采集、静止门限、错误身份拒绝、失鲜、重启与重新校准失效。浏览器代码由 CI 进行语法检查。真实动态佩戴效果需完成上述实板动作后评估，单次桌面静止检查不能证明动态精度。

2026-11-27 初次双串口读取出现缺帧后，主机接收改为保留未完成行的分段缓冲，并将写盘移到独立有界队列；未修改板端 Wi-Fi 或融合参数。复查记录为 `live-r2.jsonl`，25 秒窗口摘要为 `static-r2-summary.json`：上臂 624 帧、前臂 623 帧，序号缺帧均为 0；相对窗口起点最大姿态变化分别约 0.291°、0.056°。该窗口板端始终就绪，但 VQF 静止判定比例仅约 52%、58%，说明静止判定仍可能被噪声或轻微振动打断；不能把姿态变化直接当作已验证的精度。这个窗口以外的后续运行可能出现缺帧，需以实时计数为准。

本机主机完整测试 272 项通过，新增手臂测试 7 项包含在内；`arm_vqf.js` 语法检查通过。固件构建通过且 COM6 烧录哈希校验成功，RAM 50,036 字节、Flash 748,977 字节。实际手臂佩戴标定和动态约束精度尚待用户完成动作后检查。
