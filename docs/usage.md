# 使用与数据说明

下列命令从仓库根目录 `2.代码` 执行。固件在 `firmware/`，电脑端在 `host/`，启动与诊断工具在 `tools/`。首次安装、环境选择和编译命令见根 [README](../README.md)。

## 单板 USB 与 Wi-Fi

运行单节点开发台：

```powershell
.\tools\start_dashboard.ps1
```

打开 `http://127.0.0.1:8000/`。该入口需要 `host/requirements.txt` 中的 Python 依赖；手动运行时使用已安装这些依赖的 Python：

```powershell
python -m pip install -r host/requirements.txt
python -B -X utf8 host/run_dashboard.py
```

统一开发台现使用左侧导航切换独立工作区：`#/dashboard` 实时总览、`#/calibration` 五步标定与单节点重新标定、`#/records` 历史记录与 ZIP/CSV 导出、`#/replay` 保存姿态与同步曲线回放、`#/advanced` 高级设置。桌面总览固定单屏；窄屏允许当前工作区内纵向滚动。人体支持鼠标拖动旋转、Shift 拖动平移、滚轮和滑杆缩放。页面切换保持连接与记录状态。

历史记录页的曲线预览由浏览器读取现有 ZIP 接口完成。单个解压文件超过 128 MiB 时，请导出完整 ZIP 后离线分析。单节点结果 CSV 在分段解算后生成，可从历史记录页下载。回放 1× 使用服务原有播放功能，0.5×/2× 使用现有暂停和定位命令，实际骨架帧按保存结果展示。

### 会话删除、还原与容量

- 动作会话列表支持右键和行尾「⋯」。点「删除记录」后核对录制时间和采样数，再确认移入 Windows 回收站。整个会话目录一起移走，包括原始采样、CSV 和测量摘要。正在录制、保存或载入回放的会话需退出对应状态。
- 「回收站」独立页面只列本开发台的会话，可按条还原。历史记录上限为 30 条，达到后需先腾出位置才能新录制或还原。回收站上限为 20 条，达到后可先还原或在 Windows 回收站手动处理旧会话。
- 六面标定会话可手动标记，已被单节点测量摘要引用的静置会话也会自动显示为「标定」。删除前需先解除保护。删除确认会显示依赖该标定的测量会话。

Windows 回收站功能使用新版上位机依赖。更新后运行 `tools/start_dashboard.ps1`，或在当前 Python 环境安装 `host/requirements.txt` 后重启开发台。

USB 模式选择实际插入板子的串口，波特率 115200。连接页面前关闭 PlatformIO 串口监视器；蓝牙虚拟串口与 USB 板串口需要区分。串口打开后还应确认有有效帧、节点在线和随动作变化的数据。

Wi-Fi 模式填写板子日志中的实际地址和 TCP 端口。A 热点拓扑的历史地址为 `192.168.4.1:9000`，B 为 `192.168.4.201:9000`。电脑需要加入允许互访的同一网络；热点无 Internet 不妨碍本地网页。网页可能恢复上次地址，换网络后应检查连接参数。

`firmware/include/wifi_config.example.h` 是不含真实凭据的模板。需要重新配置固件时复制为同目录 `wifi_config.h`，填写本地参数。A/B 需要一致的热点凭据，复用已烧录的 A 时不能随意为 B 设置另一套密码。默认环境是 A；B 使用 `esp32-s3-client-b`，第三节点尚需独立环境与地址。串口号会变化，烧录前按实际 USB 设备确认。

单节点开发台操作顺序：有效数据在线 → 静置零偏校准 → 设定参考位姿 → 记录动作 → 停止记录 → 预览、回放或导出。记录与校准期间有互斥限制，按页面提示完成。参考归零只改变显示参考与位置初始化，不代替零偏或安装标定。

记录默认保存在 `host/recordings/`，每次创建独立会话。CSV 使用 UTF-8 BOM；`imu-data.csv` 保留传感器与姿态等数据，`metadata.json` 保存单位、通信方式、坐标和校准信息。回放最多抽取 5000 个显示样本，ZIP 导出保留原始记录。不得用回放或合成演示替代实测。

## 多板旋转监控

8010 监控使用标准库和本项目的纯 Python 模块，无需 FastAPI。默认启动 A/B：

```powershell
.\tools\start_wifi_monitor.ps1
```

也可以明确指定端点：

```powershell
python -B -X utf8 host/run_wifi_monitor.py --node A=192.168.4.1:9000 --node B=192.168.4.201:9000
```

打开 `http://127.0.0.1:8010/`。没有配置的槽位显示“未配置”，断开的节点显示“离线”，不生成模拟动作。A/B 各自有 TCP 连接、姿态解算、校准、参考和统计；当前三路支持是软件能力，历史实板记录只覆盖 A/B。

将板子放稳，分别点击“静置校准（4秒）”，成功后再转动。重新上电、服务重启或检测到设备更换/重启后重新校准。普通网络重连且设备时钟连续时可保留偏置。保持“停稳保持”可以抑制静置显示漂移；极慢动作可能被误判，关闭后仍保留已校准的零偏补偿。

该页面只显示相对旋转，不积分位移，不计算完整人体关节角。8000 与 8010 的校准状态不共享。详细原理与历史证据见 [旋转稳定性验证](validation/rotation-stability.md)。

## 协议与统计

新固件同时在 USB 和 Wi-Fi TCP 输出换行结束的 16 列文本：

```text
IMU2,node_id,sequence,device_us,sensor_flags,ax,ay,az,gx,gy,gz,temp,mx,my,mz,mag_temp
```

`sequence` 与 `device_us` 是 32 位无符号计数；微秒时钟约 71.6 分钟回绕。`sensor_flags` 的 bit0 为六轴有效，bit1 为磁力计有效。六轴读取失败时固件跳过该帧；磁力计无效时姿态降为六轴估计。加速度单位 g、角速度 °/s、磁场 mG、ICM 温度 °C、LIS 温度为原始值。

默认示例采样率为 100 Hz，配置允许 25、50、100 Hz。姿态积分优先采用设备采样时间；序号用于统计接收链路缺少的采样帧。该缺帧统计不是 Wi-Fi 底层无线丢包率。单节点开发台兼容旧 11 列 CSV，其时间和缺帧率只能按电脑到达间隔估计；8010 监控要求带有效元数据的 IMU2 帧。

当前没有跨板硬件采样同步。多个独立设备各自带微秒时间，不代表这些时间已经在同一时基。

## 坐标与位移

`host/coordinate_settings.json` 保留已确认的传感器轴映射 `-X / +Y / -Z`。传感器映射必须使用三条不同原始轴并保持右手系，同时作用于加速度、角速度和磁场。显示方向翻转只改变显示，不是传感器安装标定。

单节点页面保留惯性位置估算、静止约束、连续与片段模式、坐标设置和位姿回放。它用约 1 秒静置建立重力尺度基线，再积分去重力加速度。采样缺口、姿态误差、匀速误判和零偏都会影响结果；停稳清零速度不能修复已经累计的位置误差。运动优先、均衡、稳定优先三种模式通过死区与速度衰减交换小幅运动响应和抑漂效果，尚无外部位置参考验证。

### 单板短时位移测量

用 8000 开发台连接一块板并使用「开始记录／停止并保存记录」生成完整动作会话。建议用 USB，先在原始采样中核对 ICM-42688-P 的轴向和符号。保持同一块板、同一采样配置和相近温度。

1. 分别让原始传感器 +X、−X、+Y、−Y、+Z、−Z 竖直朝上。每次先放稳，再单独录制约 2 秒。记录期间保持该面静止。
2. 板卡从原始 +Z 朝上的姿态起步，把板卡 +X 对准实验台 +X，实验 +Y 按右手系确定。先录至少 1 秒静止，再做一次约 1–3 秒的移动，最后再静置至少 1 秒才停止录制。动作记录的首尾各 1 秒会用作静止窗，可按实际情况通过 `--start-still` 和 `--end-still` 指定。
3. 将命令中的目录替换为七个会话目录。下面示例的参考位移为沿实验 +X 平移 0.50 m。可以省略 `--reference`，仅输出测量值。

```powershell
host/.venv/Scripts/python.exe -B -X utf8 tools/measure_displacement.py "host/recordings/motion" --faces "host/recordings/xp" "host/recordings/xn" "host/recordings/yp" "host/recordings/yn" "host/recordings/zp" "host/recordings/zn" --reference 0.50 0 0
```

解算完成后，在动作会话目录生成两份结果文件。现有原始采样和 ZIP 仍可用于复算。

- `single_node_motion.csv` 使用 UTF-8 BOM 和 10 列中文表头。按设备时钟从动作起点取第 0、1、2…秒的姿态、瞬时速度和累计相对位移。整数秒落在两帧之间时，四元数和运动量在相邻高频帧之间插值。速度、位移用固定实验坐标并保留正负，航向以起点为零，显示在 ±180° 内。角度四舍五入到 1 位小数，速度和位移到 3 位。选择历史会话后可点击「导出单节点运动结果 CSV」。
- `single_node_motion_summary.json` 保存 `duration_s`（动作起点至所选终点静置窗的起始时刻）、`displacement_m`（实际终点三轴位移）和 `distance_m`（起终点直线距离）。例如 `duration_s` 为 2.4 时，CSV 最后一行是第 2 秒。参考值只参与验收，2% 用未舍入的三维终点误差除以参考距离判断，50 cm 对应 1 cm 误差。零位移只报告绝对误差。

用已知距离重复测量各轴、斜向和原地旋转工况，报告误差分布与无效次数。采样缺帧、重启或静置质量不足时该次拒绝出数。

当前项目优先推进可靠姿态与通信。三维模型能平移不等于已经完成准确空间定位。

## 检查与诊断

```powershell
Push-Location host
python -B -X utf8 -m unittest discover -s tests -v
Pop-Location
node --check host/web/app.js
node host/tests/test_pose_math.js
```

环境与完整验证入口以根 README 为准。仅查看原始 Wi-Fi 帧可以运行 `python host/receive_wifi.py 实际IP --port 9000 --count 100`；它会占用该板 TCP 连接，执行前应断开其他接收程序。

`tools/check_wifi_node.py` 可保存真实接收或页面接口证据，并可能使用 Windows 已保存的 Wi-Fi 配置切换网络；`--calibrate` 要求板子确实静止。这些工具属于后续明确进行硬件验证时使用的入口，目录整理与离线测试不会自动执行它们。
